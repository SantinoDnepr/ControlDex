# ControlDex

Неофіційний Android-застосунок для керування стримером **Widex COM-DEX** і підключеними до нього слуховими апаратами.
Протокол отримано реверс-інжинірингом офіційного застосунку COM-DEX 1.3.0 (`com.widex.comdex`).

> ControlDex не пов'язаний з Widex A/S і не схвалений нею. Widex і COM-DEX — торговельні марки їхніх власників. Користуйтеся на власний ризик.

Поточна версія: **0.9** (`versionCode 9`), пакет `ua.controldex`, Android 8.0+ (minSdk 26, targetSdk 34).

## Причини написання цієї програми

1. Застосунок Com dex розробники видалили з Google Play Market. Усі інші їхні застосунки від Widex не працюють з Bluetooth-приставкою Com dex 427. Ситуація, коли залізяка є, а програми немає, бо розробникам так захотілося. Неприємна, чесно кажучи.
2. Відсутність будь-якої документації щодо Com dex 427. Команди, режими, увімкнення, налаштування — нічого.
3. Під час кожного підключення оригінальна програма Com dex вимагає увімкнути геолокацію. Ну навіщо вона їм? Щоб що? Дратує.
4. Індикатор рівня заряду акумулятора Com dex запхано в такий далекий куток, що виникає питання: а хто взагалі писав це ПЗ? Він узагалі в курсі вимог і тенденцій сучасних застосунків для смартфонів? Сумно це.
5. Інтерфейс програми. Коли на головному екрані лише 2 кнопки — це жах.

## Можливості

- **Гучність** слухових апаратів: `+` / `−` (з автоповтором під час утримання) і Mute.
- **Програми**: наступна програма, перемикання Normal / Zen+.
- **Фокус** мікрофонів: центр, уперед, назад, ліворуч, праворуч.
- **Boost COM-DEX media volume** (потрібна прошивка COM-DEX ≥ 1.2.51).
- **Мікрофони слухових апаратів** під час трансляції (дзвінок, музика, Remote Mic): увімкнути / вимкнути.
- **Стан**: батарея COM-DEX і заряджання, neck loop, поточний профіль (Idle / дзвінок / музика / Remote Mic), прошивка, серійний номер.
- **Робота у фоні**: foreground-сервіс з постійним сповіщенням (кнопка «Від'єднатись» прямо в ньому), автопідключення до останнього COM-DEX під час запуску та автоматичне перепідключення після втрати зв'язку.
- **Режим Green** (типовий): GATT поверх уже наявного класичного Bluetooth-з'єднання (BR/EDR), як прихований режим оригіналу для «проблемних» телефонів. Усуває заїкання звуку під час старту музики на Redmi та подібних.
- **Теми**: світла, темна, системна.
- **Вбудована довідка** (тексти з оригінального застосунку) та екран «Про програму».
- **Діагностика** (вмикається в налаштуваннях): журнал подій GATT/A2DP/HFP, запис у файл, копіювання та надсилання журналу zip-архівом.

Інтерфейс застосунку — українською мовою.

## Як це працює

```
Телефон ──Classic BT (A2DP + HFP, звук; пара створюється в налаштуваннях Android)──► COM-DEX
Телефон ──GATT (керування, ControlDex)────────────────────────────────────────────► COM-DEX
COM-DEX ──власний радіоканал 2,4 ГГц─────────────────────────────────────────────► слухові апарати
```

Телефон не керує слуховими апаратами напряму: ControlDex записує команди «пульта» в характеристику COM-DEX,
а той передає їх апаратам. Шифрування та автентифікації на рівні застосунку в протоколі немає.

Основне:

| Що | UUID / значення |
|---|---|
| Сервіс Widex | `95986f2d-d705-4421-9890-2d32bff70000` |
| `MICROPHONE_CONTROL` | `…70003`, `1` увімк. / `0` вимк. |
| `NECKLOOP_STATUS` | `…70004`, `0` відкрито / `1` закрито |
| `CURRENT_PROFILE` | `…70005`, `0` немає зв'язку, `1` Idle, `2` HFP, `3` A2DP, `4` Remote Mic |
| `CHARGING_STATUS` | `…70007` |
| `PI_COMMAND` | `…70100`, кадри команд гучності/програм/фокуса |
| `BOOST_MEDIA_VOLUME` | `…70202`, `2` увімк. / `0` вимк. |
| Батарея, Device Information | стандартні `180F` / `180A` |

Кадри `PI_COMMAND` закінчуються двома байтами контрольної суми з невідомим алгоритмом, тому використовуються
лише готові кадри з оригінального застосунку (див. `ComDex.kt`). Повний опис профілю, послідовності
підключення та відкритих питань — у технічному завданні `../TZ_COM-DEX.md`.

## Структура вихідного коду

`app/src/main/java/ua/controldex/`:

| Файл | Призначення |
|---|---|
| `ComDex.kt` | GATT-профіль COM-DEX: UUID характеристик і кадри `PI_COMMAND` |
| `GattClient.kt` | Підключення (BLE і Green/BR/EDR), черга GATT-операцій, нотифікації, перепідключення, watchdog |
| `Core.kt` | Стан застосунку на весь час життя процесу: GATT-клієнт, останні значення, журнал, автопідключення |
| `ComDexService.kt` | Foreground-сервіс (`connectedDevice`) зі сповіщенням, не дає системі вбити процес |
| `MainActivity.kt` | Головний екран: підключення, гучність, програми, фокус, Boost, мікрофони, стан, панель налагодження |
| `PageActivity.kt` | Екрани «Про програму», «Налаштування», «Довідка» |
| `HelpTexts.kt` | Тексти довідки |
| `BatteryView.kt` | Індикатор батареї |
| `FileLog.kt`, `LogProvider.kt` | Журнал у файл і видача zip-архіву через `ContentProvider` |
| `Ui.kt` | Спільні налаштування (SharedPreferences), тема, версія |

## Збірка

### GitHub Actions

Workflow `.github/workflows/build.yml` збирає `assembleRelease` (JDK 17, Gradle 8.7) на кожен push і викладає
`ControlDex.apk` як артефакт `ControlDex-v0.9-release-build<N>`.

Для стабільного підпису (щоб нові версії встановлювалися поверх старих) задайте секрети репозиторію:

| Секрет | Вміст |
|---|---|
| `KEYSTORE_BASE64` | keystore у base64 |
| `KEYSTORE_PASSWORD` | пароль сховища |
| `KEY_ALIAS` | аліас ключа |
| `KEY_PASSWORD` | пароль ключа |

Без `KEYSTORE_BASE64` APK підписується тимчасовим debug-ключем (у журналі збірки буде попередження).

### Локально

Потрібні JDK 17, Android SDK (platform 34, build-tools 34.0.0) і Gradle. Android Studio не обов'язкова.

```powershell
"sdk.dir=D:/Android/Sdk" | Out-File -Encoding ascii local.properties
gradle assembleRelease
```

Результат: `app/build/outputs/apk/release/ControlDex.apk`. Докладна покрокова інструкція для Windows
(встановлення JDK, SDK, Gradle, встановлення на Redmi через `adb`) — у [BUILD_LOCAL.md](BUILD_LOCAL.md).

Локальний підпис тим самим ключем, що й у CI: задайте змінні середовища `SIGNING_KEYSTORE`,
`SIGNING_STORE_PASSWORD`, `SIGNING_KEY_ALIAS`, `SIGNING_KEY_PASSWORD`.

## Перший запуск

1. Спаруйте COM-DEX у системних налаштуваннях Bluetooth: відкрийте й закрийте neck loop, виберіть пристрій з іменем `COM-DEX`.
2. Запустіть ControlDex, натисніть «Під'єднатись» і дайте дозвіл «Пристрої поблизу».
3. На Xiaomi/Redmi (MIUI) у «Налаштуваннях» застосунку вимкніть оптимізацію батареї та увімкніть автозапуск —
   інакше система може розривати з'єднання у фоні.

Поки neck loop відкрито або COM-DEX заряджається, керування недоступне, показується лише стан.

## Діагностика

1. «Налаштування» → увімкнути «Налагодження».
2. На головному екрані з'являться кнопки «Оновити стан COM-DEX», журнал і «Поділитися (zip)».
3. Через `adb`: `adb logcat | Select-String -Pattern "ControlDex|Bluetooth"`.

## Обмеження

- Читається батарея самого COM-DEX; заряд слухових апаратів протокол не віддає.
- Нові команди `PI_COMMAND` сформувати неможливо (алгоритм контрольної суми не розкрито).
- Застосунок не створює пару з пристроєм: сполучення виконується в системних налаштуваннях Bluetooth.
